# CLEANOPS 360 — SPRINT PLAN

**Estado:** Especificación documental preimplementación, 2026-10-09. **Jerarquía:** Product Master V3 (visión) → SRS V1.1 (normativa) → este documento (diseño derivado). Ningún endpoint o pantalla se considera implementado.

## Plan de entregas verticales — no calendario ficticio
Los sprints son unidades de alcance y no prometen fechas/velocidades no estimadas. Dependencias acordes ROADMAP fases 0–20.


## Sprint documental previo

Cerrar contratos técnicos de Foundation y Auth, diagrama despliegue, parámetros bloqueantes, threat model, matriz por REQ y checklists manuales.


## Primera entrega

Fase 0 completa: entorno y System Status visible; pruebas operativas y aceptación manual.


## Segunda entrega

Fase 1 completa: auth, MFA, sesiones y recovery; UI real más backend y test de abuso.


## Continuación

Fases 2–20 siguiendo ROADMAP; subdividir en slices funcionales completos; no hacer todas las tablas antes de las pantallas.


## Gate

Cada sprint acaba con prueba real UI→API→DB→UI; dependencia bloqueada sin aceptación.
