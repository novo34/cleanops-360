# B1 TOTP verifier increment

Base: 4cb08128ff2203929b727b05a0fc190a9d544f36, PR #7. AUTH-GATE-05 remains OPEN.

- Uses OTPAuth 9.4.1 (RFC 4226/6238, maintained library), pinned with its @noble/hashes 1.8.0 dependency. V4 trial configuration supplies period=30 seconds, digits=6, window=1 on each side. No canonical values are modified or promoted to production defaults. HMAC algorithm comes explicitly from the trusted method record (SHA1/SHA256/SHA512), never a request selector or implicit library default.
- Internal entry point: verifyTotpFactor. The private adapter must resolve a trusted server context (user, tenant, method, authorized purpose, ceremony), verify method status/revocation and ceremony authorization, and return an exactly matching record with method version, expiry and last consumed counter. Pending enrollment is only eligible for its confirmation ceremony; other purposes require an active method.
- Successful cryptographic verification requires consumption via compare-and-swap of the method-global counter. The persistence key is user/tenant/method, NOT purpose/ceremony: changing purposes cannot reuse a counter. The callback must atomically recheck current authorization, method state/version, expiry and expected counter, require monotonic advancement, consume the ceremony and audit in the caller's transaction. Return false for a race/revocation/replay. Nothing may issue a session or escape as success before commit. No full adapter or persistence is introduced here.
- Secret records contain no plaintext. An authenticated decryption callback must bind ciphertext to method/user/tenant/version and return a fresh owned byte buffer. The verifier wipes its owned plaintext and library copy on all exits; JS cannot guarantee complete erasure. It never creates a provisioning URI, logs codes/secrets, returns them or attaches dependency causes to errors. Encryption/key management stays with the pending private adapter.
- Invalid/reused/expired codes and mismatched context return the existing generic AuthError(401) for failed-attempt accounting. Dependency/decryption/corrupt-method/clock errors throw generic AuthError(503) for rollback. Trusted time is checked again after asynchronous decryption. Rate limits remain the existing B1 adapter's responsibility. A factor proof itself grants no identity, permission or session.
- Tests: independent RFC 6238 vectors for three algorithms; current/adjacent/outside windows; incorrect and malformed codes; binding mismatches; ceremony expiry; counter reuse/backward windows; concurrent CAS (one winner); replay across purposes; revoked version; dependency/persistence errors; clock delay; secret wiping and context mutation.
- Validation uses the existing B1 no-database GitHub Actions workflow: install, lint, typecheck, Node tests, Vitest and build. No local checks claimed. Final run results are recorded on PR #7. Dependency metadata comes from upstream v9.4.1; the OTPAuth archive is version-pinned without inventing an integrity value.

Runtime remains closedBackend. No PostgreSQL, migrations, grants, production activation, merge or deployment. Persistent replay resistance and authorization rely on the documented atomic callback, which still needs a real private adapter and integration validation.
