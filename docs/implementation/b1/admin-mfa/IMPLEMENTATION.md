# REQ-AUTH-034 — administrative MFA reset

Implementation of the already approved C-SCOPE and SQL11 `auth_api.admin_reset_mfa(uuid,bytea,text,uuid) RETURNS boolean`; no SQL/ACL/signature change or additional role permission. Original14 canonical HTTP operations remain byte-identical. One additive route POST /auth/mfa/reset maps the existing independently attested MFA_RESET receipt, target and reason into that exact broker function. Request schema reuses AuthorizePasswordResetInput; response is only `{data:{reset:true},meta}` after COMMIT. No factor, ticket, recipient, target state or private audit metadata is returned.

ACTIVE, Origin/CSRF, duplicate-key rejection, existing protected-action rate budget, fresh B1-SELF-06, owned one-time idempotency and underlying edit/users + manage_permissions/access checks are mandatory. The grant supplies no RBAC power. Tenant/actor/version are resolved on the server. SQL revalidates receipt purpose, target tenant/user, credential version, expiry and consumption under the approved locks, revokes only the target's factors/recovery material/sessions/trusted devices/challenges and writes actor/target/date/outcome audit plus independently attested identity evidence/reason. Self and foreign targets deny. No session is issued; actor ACTIVE cannot be cleared or transitioned by this operation.

Existing AuthPanel gains a form for the independently verified receipt, target and reason, reusing its step-up/pending-action mechanism. No storage/logging of the receipt; the form is cleared immediately and pending memory follows existing ceremony cancellation/expiry rules. Runtime routes still use closedBackend; only the isolated test composition can execute the backend.

Prepared real Chromium cases: successful UI reset of a logged-in target, correct durable audit/reason and revocation without actor logout; password PREAUTH denial; expired/foreign/forged inputs; actual pre-COMMIT termination with rollback of factors/receipt/audit and safe retry. Tests use the existing authorized verifier role and synthetic identity attestation. They do not establish a productive identity-verification provider or external infrastructure.
