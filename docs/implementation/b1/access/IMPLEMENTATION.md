# AUTHZ public vertical — implementation under isolated validation

C-SCOPE includes AUTHZ within B1. No additional module and no SQL/ACL modification. Existing five approved permission mutations, effective_access and access_detail are mapped through lib/b1/access-http.json; canonical V4 bytes are unchanged. ACTIVE/CSRF/Origin/owned one-time reservations remain mandatory. POST selects only one fixed approved function; request role/target/resource UUIDs are locators, not authority. Tenant and actor are always the resolved locked context. Expected policy is a CAS claim, never authorization. PostgreSQL validates RBAC, no-overdelegation, temporal windows and fresh B1-SELF-06 step-up under its exclusive tenant-policy lock before effects/audit. The HTTP layer deliberately avoids an earlier binding_authorization SHARE lock on policy mutations. No direct table access, dynamic SQL or user GUC.

The existing auth panel hosts Administration → Users → User Detail → Manage Access. It projects current roles/rules and server can_manage decisions, role creation/editing, membership, role/user rules and revocation with explicit dates. Permissions are evaluated again for every API request; no role label grants authority. Errors preserve ACTIVE; result/cookies are never emitted before COMMIT. Browser memory only; no localStorage/sessionStorage or secrets in logs. SQL changes require separate approval; closedBackend remains connected, AUTH-GATE-05/B1 OPEN.

Required acceptance includes the canonical RBAC audit contract (before/after/actor/reason, relevant denied changes). Those properties are explicitly asserted against actual durable audit rows after functional browser tests; a count-only success audit is not silently treated as complete. Synthetic role grants/resources in fixtures exercise contracts only and do not approve productive role assignments. No new requirement is accepted from these unit/static preparations.
